# v0.8 — first-run setup

## User outcome

A first-time user installs the complete checkout with `/bin/sh install.sh` (Codex), `--host claude-code`, or `--host both`, opens a subtitled lecture in Aside, and asks the installed skill to study together and open/prepare a question chat. The user chooses a lecture title and, only when necessary, a player. The agent handles identifiers, selectors, private session paths, study initialization and native chat binding.

The five-minute goal assumes an existing logged-in Codex/Claude Code host and a connected Aside app/profile/official CLI. App download, account onboarding, host permissions and unsupported chat openers remain external steps. A new human user's full installation-to-chat time has not been measured; this record does not claim that benchmark passed.

## Implemented flow

- `install.sh` uses POSIX shell without Node/npm/network access. It symlinks the complete local checkout into the selected host's personal skill directory, honors `CODEX_HOME`, checks every destination before linking, preserves existing skills, and is safe to repeat for the same checkout. It prints the actual skill path and host-specific first prompt. The repository must stay in place.
- `setup` checks the actual runtime/image worker, lists titles plus URL origins, and provides actionable browser connection steps. It omits signed URL paths/query data. The host resolves the user's chosen title; it does not silently pick the active or first tab. `--query` narrows a truncated list.
- `setup --tab ID` discovers observed video/iframe players, enabled caption tracks, unique DOM subtitle IDs/classes and unique structural selectors where IDs are absent. Ambiguous players require selection. Offscreen media are excluded; clipped players require inspection. Accessible iframes without a unique video are blocked. Cross-origin frames retain an explicit snapshot warning.
- `start` rechecks that selection and uses a fresh private session. It starts capture and initializes study plus one question-chat reservation together. The first caption and selected PNG provide smoke evidence without stopping/restarting the collector. The worker can open the host chat while capture continues.
- `question-chat-required` provides the real reservation metadata and a private prompt file. The skill uses supported Codex native chat tools, then binds the returned actual thread ID. The CLI does not claim to create a chat. Claude Code gets an interactive full-tool command using its existing login, or a prompt-file handoff when its host has no opener.
- `check` verifies a live recorded capture PID, lock and recent status, actual caption evidence, an inside-session saved PNG, and bound chat metadata. Missing evidence, a dead process, an unbound reservation or stopped capture cannot report ready. This is a point-in-time local check, not a host chat API verification or continuing monitor. The skill also inspects the first cropped image before announcing readiness.

Existing manual/ego capture, Q&A isolation, provenance checks, receipt handling and combined-note export remain available. Guided first-run discovery currently targets Aside; it is not a new Chrome adapter or ego task-space discovery mechanism.

## Baseline and independent review

An independent agent read the previous README/skill without the implementation plan. It identified missing copyable installation/first-invocation instructions, manual tab/player investigation, separate smoke/full captures and study initialization, and native chat creation/binding spread across references. Those concrete obstacles informed the new entry point.

Independent code review reproduced two selection problems: a resource iframe with no video could be promoted to a player, and offscreen media could add an unnecessary choice. Both were corrected. A later review caught a mismatch where screenshot validation still counted offscreen iframes; its public `setup → start` regression failed before the visibility predicates were aligned, then passed. The final reviewer reported no remaining findings in the reviewed code. The review did not perform live browser/chat actions.

Readiness was also strengthened against counters surviving a dead capture or a missing frame. Recommended start arguments preserve an explicitly selected question host. Each behavioral correction has a failing-before/passing-after regression under `.superpowers/v08/`.

## Verification

- Full unit/subprocess suite: **85 passed, 0 failed** with Aside-managed Node v26.5.0 and PATH restricted to `/usr/bin:/bin`.
- Installer tests exercise both hosts, paths with spaces/apostrophes/Korean, execution with no PATH Node/npm, repeat installation, and preservation of existing skills before another host is changed.
- Public onboarding tests exercise title selection, URL redaction, automatic selector discovery, player ambiguity, missing Aside, resource/offscreen frames, actual evidence/PID readiness, initialized study, one chat handoff, binding/reuse, continued capture and output-directory protection. Bound IDs in these subprocess tests are explicitly simulated.
- `test/onboarding-browser-integration.mjs`: **passed** in installed native Aside, default auto caption mode. The final short localhost run measured **698 ms** for selected-tab discovery, **1,696 ms** for `start` through first caption/PNG plus question-chat handoff, and **7,868 ms** for the entire fixture script including opening/closing its own tabs and additional discovery checks. These timings exclude download/sign-in, human selection, native chat creation and model response time.
- The native script also checked a player without an ID and class-only subtitles. Actual native chat creation was deliberately not invoked; the handoff remained unopened/unbound and `check` correctly refused readiness.
- The complete earlier native capture regression script was rerun after the shared iframe visibility fix: **passed** nonzero/scrolled crops, rapid DOM captions, TextTrack pause/rate/end, cross-origin fallback and concurrent public-CLI Q&A/export.
- Independent forward testing used only the updated README/skill, an isolated host installation and the snapshot subprocess fixture. The only simulated user input was the lecture title. It confirmed a cropped PNG, no duplicate study initialization, unchanged worker state across explicitly simulated chat binding, reuse of the same reservation, and normal stop/lock cleanup. It did not create a native chat.
- The installed launcher was run again through the real Codex skill link; default `setup` without account/profile options returned a valid title-selection response. No user lecture was open in that default listing.
- Shell syntax checks, skill frontmatter validation and `git diff --check`: **passed**.

An initial native test harness attempt incorrectly parsed the existing text output of `stop` as JSON; the harness was corrected. The next native test exposed class-only subtitle discovery falling back to snapshot; scoped unique class detection fixed it, and the native rerun passed. An independent subprocess forward test initially used default DOM events against a snapshot-only VM fixture; that fixture lacks a browser `window`/event environment. Its documented snapshot mode is used for that boundary test; the real native default-auto run above validates the actual browser event path.

Private native logs/journals/PNGs are under ignored `.superpowers/v08/` and `sessions/aside-onboarding-20261021-final/`. Tests close only their owned tabs/processes. The installed Aside app, user profile and existing skills are retained.

## Host and coverage limits

Native capture plus Q&A/export were previously demonstrated in [v0.7.1](2026-10-21-v071.md); actual Codex question-chat creation was demonstrated in [v0.4](2026-10-20-v04.md). This onboarding run checks the prepared host handoff and separately simulated binding, rather than claiming a fresh native chat opener demonstration.

Claude Code personal skill placement and `--append-system-prompt-file` follow its [official skill documentation](https://code.claude.com/docs/en/skills) and [CLI reference](https://code.claude.com/docs/en/cli-reference). The currently installed legacy Claude CLI's help command failed under this machine's selected Node 26 before displaying help. Its global installation was not changed, and a native interactive Claude question session was not tested. The skill therefore supplies a supported-host/manual handoff and preserves the fallback of pasting the prompt into a full-tool session; automatic opening is conditional on actual host support.

No speech recognition, audio capture, model API keys or background model daemon were added. Unknown media times, snapshot incompleteness, cue coalescing, protected-video limitations and the need for a real-course long-session test still apply. Collector model-call counters do not measure this conversation's tokens or tutoring-agent usage.
