# Lecture Companion v0.6 — Aside runtime discovery

## Result

The existing launcher now automatically detects Aside's managed standalone Node at `~/.aside/runtime/node/bin/node`, honoring the app's `ASIDE_HOME` override. It requires an executable Node 22+ and selects it after explicit `LECTURE_NODE`, before the Codex bundle/ego/existing PATH fallback. Missing or incompatible Aside runtimes do not trigger downloads, installation, repair, authentication, CLI agent tasks or permission changes.

Generated question commands preserve the selected Aside executable. A fresh question chat therefore does not need to inherit the worker's custom ASIDE_HOME or have Node on PATH. Study, Q&A and image processing use the same existing implementations.

## First-party capability verification

- [Aside's official component history](https://docs.aside.com/changelog/components) documents its managed Node/Python runtime feature and runtime install verification.
- [Official CLI/REPL documentation](https://docs.aside.com/help/developers) exposes browser automation rather than a general Node invocation. The signed CLI distribution's `guide repl` explicitly prohibits imports and require. The inspected CLI help does not list `runtime`; treating unknown words as an agent prompt would be an inappropriate detection strategy.
- The official macOS browser distribution served by `https://aside.com/api/download/macos` identified browser package 1.0.928.1. Read-only inspection confirmed that its app home defaults to `.aside`, honors ASIDE_HOME, and manages the runtime separately under `runtime/node/bin/node`. The disk image was mounted read-only and ejected after inspection. No browser app was installed or launched.
- [Official runtime metadata](https://releases.aside.com/runtime/aside-runtime-darwin-arm64-latest.json) identified runtime **1.26.1019.335** for darwin-arm64. The development verification used its exact archive at `https://releases.aside.com/runtime/1.26.1019.335/aside-runtime-1.26.1019.335-darwin-arm64.zip`.
- Archive SHA-256 matched **ff841f37fea613bc39ad91f883f21f1bfbca8155262f774e7a1948ddc0f43bd4**. The staged Node executable passed macOS code-signature verification and reported **v26.5.0**.

The downloaded materials were development-only artifacts in the ignored verification folder. They are not part of the repository distribution or a runtime downloader. CLI help initialized a small update-check cache; that task-created cache was removed and the original absent default Aside home restored. No login, agent task, browser profile or account configuration was created.

## Actual Aside-managed runtime demonstration

Aside was not installed on this computer. Instead, the genuine verified runtime executable above was staged privately in the app's observed layout. A complete copied checkout excluded `node_modules`; PATH was restricted to `/usr/bin:/bin`. The launcher was given only ASIDE_HOME and selected `provider: aside` automatically.

- Actual encode/decode, image worker and duplicate filtering diagnostics passed through Aside's Node.
- A synthetic 22-event lecture journal was initialized and offered to a worker.
- The emitted question-context command succeeded in a fresh environment with ASIDE_HOME removed, using the selected managed executable.
- One synthetic question/answer pair saved without changing the worker's pending receipt or study file.
- The worker committed all 22 events in follow mode and exported combined lecture records and Q&A. The answer retained its original summarized position 0, while final worker coverage reached 22.
- Private ignored results: `sessions/runtime-v06-20261021-aside/validation.json`, `notes.md` and `study-notes.json`.

This tests the actual managed Node and application layout, not an installed Aside browser, a live lecture or native Aside chat creation. The staged runtime was not installed globally, added to PATH or placed into the user's default Aside home.

## Independent review and limits

One read-only reviewer examined only the delta against `eeedab8`, ran all **11 runtime tests**, and found no Critical, Important or Minor issues. Actual signed-runtime behavior, path provenance and browser/native-chat adapters were reserved for the author's checks or excluded. No second review round was run.

An already provisioned Aside-managed runtime must exist for that provider to be selected. The launcher checks availability and falls back; it does not bootstrap or repair Aside itself. Automatic shell launching remains macOS/Linux; Windows automatic launching was not added. Lecture browser capture remains the ego adapter. Aside runtime detection does not imply an Aside browser capture adapter or native question-chat opener. No new real-lecture run, token measurement, public upload, package publication or push was performed.
