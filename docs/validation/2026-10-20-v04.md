# Lecture Companion v0.4 validation

## Result

The lecture worker and question chat now share durable local files instead of a continually forwarded conversation. The worker keeps its own mode, pending receipt and committed cursor. On each question the separate chat reads bounded fresh context, answers, atomically saves the linked pair with its exact source snapshot, and ends its turn. The worker's final export merges saved Q&A and identifies the included question revision.

The installed Codex skill prepares a reserved opening, creates and opens the question chat with supported native host tools, binds the real thread ID and reuses it later. The CLI prepares/binds state; it does not itself invoke native chat tools. Interrupted openings can be inspected and bound, or retried with the matching setup ID only after confirming that the earlier attempt created nothing.

## Independent review corrections

One read-only reviewer found three Important issues and no Critical issues. Each was reproduced as a failing regression and corrected:

1. Recent context windows hid older explanation/Q&A keys. `study context --query` now searches all saved item text/keys locally, returns bounded results/references, and supports pagination. An empty query provides bounded item discovery; `--item` reads oversized matching records. The question prompt/reference documents this route.
2. A reserved opening that stopped before native creation could not resume. Recovery now regenerates the role prompt. Explicit `--retry-setup` permits only a matching unbound reservation, after a confirmed unsuccessful opening; stale bindings and retries of bound chats fail. Unknown native outcomes still require inspection rather than automatic duplicate creation.
3. Q&A accepted invalid provenance metadata. The original ISO timestamp and an integer summarized position within the captured prefix/current worker cursor are now required. Saving later never substitutes the worker's newer cursor for the answer's original snapshot.

The author verified these corrections with regressions and the final complete suite. No second review round was run.

## Host and capture limits

- Direct computer-use control of the Codex app was denied by the tool's safety restriction. The supported native `create_thread`/navigation tools were used without bypassing that restriction. They open a dedicated question chat; this is not a claim that a literal `/side` pane was automatically invoked.
- Claude Code can use the same context/Q&A commands and generated role prompt. Automatic opening needs an actually available full-tool session mechanism. `/btw` has no local file tools and cannot implement this workflow by itself. Automatic Claude opening was not tested.
- The host still invokes commands and schedules model turns. Shared files do not continuously inject context or wake the question chat. Both chats use the user's existing host/model settings; no separate model API integration was added.
- Capture limitations remain: no audio/STT, no complete-transcript promise, Fastcampus/Kollus snapshot fallback at 500ms with unknown media time, and no bypass of protected players.
- Exact token usage and savings were not measured. No public repository, package release, push or course-content upload was performed.
