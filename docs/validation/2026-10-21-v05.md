# Lecture Companion v0.5 validation

## Result

Supported app environments no longer require a separate user Node/npm installation. The macOS/Linux launcher selects an explicit host runtime, a compatible local Codex bundle, ego's embedded runtime, or an existing compatible Node. It never downloads binaries or installs packages. The complete repository includes the unmodified pngjs 7.0.0 runtime, original MIT license and source/archive provenance under `vendor/`.

Capture, study and Q&A use the same launcher. Generated question commands rediscover the app runtime; when the agent explicitly selected a non-discoverable host Node, that verified selection is carried into the generated command. No global shell configuration is changed. Legacy `.mjs` commands remain available for callers with an explicit host runtime.

The ego shell-bootstrap unit test substitutes only the host CLI boundary with a real Node process. The local socket and image process are real. The separate actual-app checks exercise ego's real embedded runtime; no new browser page was controlled.

## Image worker and shutdown

The existing worker remains isolated from caption reads, with one pending image, timeout and bounded backpressure. Standalone app Node uses fork IPC. Ego-only execution uses the documented `ego-browser nodejs` command plus a private Unix socket and authenticated startup, since ego's helper execPath cannot be treated as a standalone Node binary. No worker_threads or browser restriction changes were introduced.

A timeout regression exposed that repeated `close()` calls could return before the first close completed. Shutdown callers now await the same close promise. The regression verifies child termination and private IPC cleanup; ordinary fork-worker tests also remain green.

## Actual ego runtime synthetic capture

A synthetic page object ran the existing collector inside real ego Node, with the new ego image runtime. It generated **13 caption events** and saved **one frame**, then honored STOP and ended normally. Largest measured observation gap was **145ms** in this short fixture. No actual website, course, browser screenshot or audio was captured; this is a runtime/concurrency smoke test, not a lecture capture benchmark.

Private ignored output: `sessions/runtime-v05-20261021-ego/validation.json`, `status.json`, journal and synthetic PNG. The ego update notice was observed; no upgrade was performed.

## Independent review

One read-only reviewer ran all nine then-current runtime/worker tests successfully and reported two Important issues, with no Critical or Minor issues. Both reproduced as failing tests before correction:

1. A configured host runtime was missing from the question command. The launcher command now preserves that verified explicit selection so a fresh chat without the original invocation environment can read context.
2. The declared package executable failed when invoked through a POSIX package-bin symlink. The launcher now resolves relative/absolute link chains, with a bounded cycle guard, before locating its entry point.

The author verified both fixes and ran the final complete suite. No second review round was run. Vendored upstream internals, actual browser/lecture behavior, Windows automatic launching and Aside adapters were outside the review scope.

## Scope and remaining limits

- The complete checkout/distribution is required: a skill-only copy without its linked library/vendor files is insufficient. Runtime packaging does not replace repository/skill installation.
- Automatic bootstrap is macOS/Linux. Windows can invoke the `.mjs` utilities using a host Node, but no PowerShell bootstrap or Windows question-command templates were added.
- Aside runtime discovery and Chrome/Aside browser adapters are unimplemented/unverified. The capture adapter remains ego. A page JavaScript engine alone is not a host Node runtime.
- A supported runtime must actually be available. Missing capability is reported; there is no automatic runtime download or user Node-install requirement.
- v0.4 native question chat creation was not repeated. Generated-command handoff is covered by isolated CLI tests. No new real-lecture trial, exact token measurement, public upload, package publication or push was performed.
