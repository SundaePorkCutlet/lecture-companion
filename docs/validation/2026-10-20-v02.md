# Lecture Companion v0.2 validation

## Result

Event-based caption collection is available for accessible selected players. Native `captions`/`subtitles` TextTracks use cuechange; explicit subtitle elements use MutationObserver. Caption reading and image processing run independently. Selected PNGs preserve the entire player; only the comparison masks the bottom 20%.

The tested Fastcampus/Kollus cross-origin player still uses the explicit accessibility snapshot fallback. This release does not bypass iframe restrictions and does not capture audio. A new lecture-wide latency/token measurement was not performed.

## Evidence

- Final `npm test`: **24/24 passed**. Includes actual child-process PNG processing, duplicate filtering, worker crash/timeout/backpressure, slow screenshot concurrency, cancellation in both directions, media end, caption clears, queue overflow, final queue draining, metadata-track exclusion, and iframe document replacement.
- Real ego browser fixture tests passed for rapid DOM captions (including clear/repeat), acknowledgment, overflow, actual TextTrack cuechange with observed media time and ended event, same-origin iframe access and explicit cross-origin refusal. These tests use synthetic local players, not course recordings. Later review fixes were checked by the final regression suite; boundary-selection tests use narrow DOM doubles rather than claiming an additional browser replay.
- `skill-creator/scripts/quick_validate.py skills/lecture-companion`: passed. The installed personal skill links to this repository and picks up the update.
- External Node worker was exercised from ego's actual embedded runtime against a locally stored PNG. No browser security/signing settings were changed.

## Controlled delay measurement

Final smoke run: two seconds in ego's embedded runtime, a synthetic caption change every observation, 20ms target read interval, 200ms injected screenshot delay, one stored 2080×1080 PNG, and 350ms image sampling target.

| Measurement | Result |
|---|---:|
| Caption observations / changes | 95 / 95 |
| Largest caption observation interval | 58ms |
| Largest screenshot operation | 202ms |
| Largest image processing operation | 96.1ms |
| Images sampled / selected | 6 / 1 |
| Completion | stopped normally |

This demonstrates that a slow image operation no longer blocks the subtitle loop in the controlled fixture. It is not an end-to-end lecture latency guarantee, a completeness percentage, or a token savings estimate. The former serial implementation failed the slow-screenshot regression with only two caption observations; the new regression requires at least ten during the same 250ms scenario.

## Review fixes

One independent code review identified five issues, all fixed with regressions:

1. Ignore metadata/chapters tracks when selecting subtitles.
2. Verify the current iframe Document identity rather than trusting an old node's isConnected flag.
3. Freeze/drain/close captions before waiting for pending image work, avoiding lease expiry during normal shutdown.
4. Recheck cancellation before acknowledging a pending caption response after image-side control loss.
5. Persist disappearance as caption-clear before acknowledgment.

The stop path additionally samples the final DOM value before freezing, then drains remaining events. No second reviewer pass was run; the fixes were verified by the regression suite.

## Runtime decision

worker_threads passed host Node tests but disconnected ego's embedded runtime. An external standard Node process worked. Advanced IPC serialization then exposed a Node/V8 version mismatch, so the worker uses JSON/base64 IPC with the CLI's Node executable and a clean execArgv. This adds process/encoding overhead while keeping image CPU work out of the collector runtime. At most one image is in flight, with a ten-second worker timeout.

## Remaining limits

- Cross-origin snapshot fallback can miss captions shorter than its actual polling interval and has mediaTime=null. Browser operations may still serialize.
- Reloads can lose undrained in-page events; loss of the selected document stops capture. Queue overflow is reported, not reconstructed.
- A same-task DOM mutation sequence can coalesce before MutationObserver runs. Burned-in subtitles are unsupported.
- Bottom-only changes and very small annotations may fall below the comparison mask/threshold even though selected images retain the bottom content.
- Multiple enabled caption tracks use the first showing, then first hidden caption/subtitle track. There is no language-selection option yet.
- The host tutoring conversation still reuses its accumulated context. No new monetary or token-reduction claim is made.

Code and fixture tests remain local on codex/lecture-companion. Private lecture captures and trial notes remain under ignored sessions/ and were not published.
