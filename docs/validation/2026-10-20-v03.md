# Lecture Companion v0.3 validation

## Result

Study sessions now separate captured, provided and committed evidence. Question mode saves the question while the independent collector can continue. Catch-up returns the original pending receipt and subsequent events in order. A validated commit saves study records and event dispositions atomically with cursor advancement.

Lecture observations, AI explanations, corrections, linked Q&A and unresolved questions are separate record types. Exports derive combined Markdown and JSON from durable study state and retain source event IDs, observed media/wall timestamps and capture uncertainty. These commands do not run a model, infer learner understanding or automatically control playback.

## Independent review and fixes

One independent read-only reviewer examined `a4018a1..583163b`, ran the then-current 38-test suite and reported four Important issues, with no Critical issues. Each reproduced as a failing regression before its fix:

1. A partial export followed by new capture invalidated its previous ownership reservation. The reservation now carries forward the validated on-disk hash before planning replacement content.
2. Directly writing a new output could leave an unrecoverable partial file. New files are written to complete same-directory temporaries and published with exclusive hard links; existing owned files use atomic rename. A child-process test injects a partial write and confirms that no partial final output is published and retry succeeds.
3. Standalone notes could reference journal evidence outside committed/pending fingerprints. State now anchors all observed journal evidence at initialization and successful mutations, independently of cursor advancement.
4. Pending receipts and direct evidence reads could expose a frame whose path was replaced with an external symlink. Paths are revalidated before each such response as well as initial offering, commit and export.

The fixes were verified by the author with regressions and the full green suite; no second independent review was run. Internal study state schema is 2. Development-only unanchored schema 1 is rejected rather than silently trusted; raw capture journals and existing manual lecture notes are unchanged.

## Remaining limits

- The host AI invokes the workflow and decides when to explain. This release does not automatically hear questions, wake model turns or provide an always-on overlay.
- Tested Fastcampus/Kollus remains the 500ms accessibility fallback with unknown media time/playback state. Accessible players expose observed playback transitions; no browser restriction is bypassed.
- No audio, ASR, automatic replay or reconstruction of missing speech. Delay events and actual queue overflow retain distinct meanings.
- Export and state tests cover ordinary process/file-operation failures. They do not prove durability across hardware failure or power loss. Exclusive new-file publication requires filesystem hard-link support and fails without overwriting an existing file when unavailable.
- Local file references are validated when supplied; changes after a response cannot be prevented by a path-only interface.
- Host conversation context still accumulates. No new token savings percentage or monetary estimate is claimed.
- A new real-lecture co-study trial was not performed. No public repository, package release, push or course-content upload was performed.
