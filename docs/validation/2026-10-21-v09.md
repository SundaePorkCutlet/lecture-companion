# v0.9 — self-contained skill package

## Installation outcome

Installing only `skills/lecture-companion` now includes the collector, CLI, image worker, vendored PNG library and original licenses. The installed launchers resolve everything under that skill's `scripts/runtime/`; they never import a parent checkout. A normal host skill-folder installation is sufficient.

The release ZIP includes the same complete skill and an optional POSIX installer at `lecture-companion/scripts/install.sh`. It copies to Codex, Claude Code, or both without Node, npm or network access. The checkout's root installer delegates to that helper. Downloaded source can be removed after installation. The ZIP is **96,424 bytes**; its explicit payload has **61 files / 226,258 bytes** before ZIP directory entries/compression. A companion SHA-256 file is generated locally. These checks detect incomplete or changed contents; they are not a publisher signature.

The existing browser/host still supplies Node 22+ and the browser connection. Aside's managed runtime, the local Codex bundle and ego's supported embedded execution remain available as before. No platform-specific Node executable is shipped. macOS/Linux have an automatic shell launcher; Windows still requires an explicit supported host Node invocation.

New guided sessions live outside the installation, under `~/.local/share/lecture-companion/sessions/`, an absolute `XDG_DATA_HOME/lecture-companion`, or an absolute `LECTURE_COMPANION_DATA_DIR`. Explicit `--out` remains supported. Empty data-root configuration uses the default; a relative explicit data root is rejected. Old sessions are not moved or deleted and remain accessible at their existing explicit paths.

## Maintainer and installer behavior

- Root `bin/`, `src/` and `vendor/` remain canonical development code. `npm run build:skill` generates the checked-in runtime, complete `FILES` index and `BUNDLE.sha256` manifest. `npm run check:skill` and the test suite reject stale payloads.
- `npm run package:skill` creates the ZIP and its hash from an explicit file map. Sessions, private logs, tests, Git state and node_modules are excluded. Users do not run this build step.
- The installer verifies the complete source, staged copy and destination. Same intact release installation is repeatable. Existing differing/modified real skill directories and unrelated links are preserved; updating another release uses the host skill manager or requires moving the old skill aside.
- Only a legacy link to this exact source directory can migrate automatically to a real copy. A failed publication restores that link. Installer locks/staging are private and only owned temporary paths are cleaned up.
- Build inputs and generated destinations must be regular files/directories. Every destination and ancestor is checked before generated files are removed or written. Generated runtime cleanup refuses unmanaged extra files.
