# Lecture Companion v0.3 — 동반 학습 세션 설계안

상태: 사용자 승인 후 v0.3 구현 완료. 아래는 v0.2에서 출발한 설계이며, 구현·검증 결과와 남은 한계는 [검증 기록](../../validation/2026-10-20-v03.md)에 정리했다.

## 목적과 성공 기준

사용자는 이미 로그인해 수강 중인 강의를 AI와 함께 공부하고, 강의 내용과 AI의 부연설명을 합친 문서를 원한다. 질문에 답하는 동안에도 강의의 새 증거를 모으고, 답변 후 지나간 내용을 순서대로 이어서 다루는 것이 이번 버전의 목적이다.

핵심 원칙은 **수집한 내용, AI에 제공한 내용, 설명·정리까지 저장한 내용을 구분하는 것**이다. 자막을 읽었다는 이유만으로 학습 기록이 완성됐다고 표시하지 않는다.

성공하면 사용자는 다음 흐름을 사용할 수 있다.

1. 강의를 보면서 새 자막과 선택된 화면에 근거한 짧은 보충 설명을 받는다.
2. 질문하면 AI는 질문에 답한다. 독립된 기존 수집기는 계속 관찰한다.
3. 답변을 마치면 질문 중 쌓인 증거부터 이어서 읽는다. 관찰 지연·유실·되감기를 함께 표시한다.
4. 강의 내용, AI 설명, 정정 사항, 질문과 답변, 남은 의문이 구분된 학습 문서를 얻는다.

## 설계 시점(v0.2)의 구현에서 출발하는 부분

- `src/core.mjs`의 `Journal`은 수집 증거와 바이트 제한 배치를 제공한다.
- `src/ego-capture.mjs`는 자막과 이미지 수집을 독립적으로 실행한다.
- `src/caption-source.mjs`는 접근 가능한 플레이어에서 자막·seek·ended를 수집한다. 플레이어 상태에 paused가 있지만 재생/일시정지/배속 전환 이력은 저장하지 않는다.
- 현재 스킬은 파일 저장 후 수동으로 커서를 갱신하도록 안내한다. 세션 상태, 근거 검증, 재시도 처리는 라이브러리가 보장하지 않는다.
- Fastcampus/Kollus의 기존 접근 방식은 500ms 접근성 관찰이며 mediaTime이 없다. 이를 개선된 시각 정보로 오인하지 않는다.

## 접근 방식 비교와 선택

1. **기존 수집기 위에 학습 세션 계층 추가 — 권장.** 증거 수집은 유지하고, 질문/따라잡기 상태와 기록의 저장을 관리한다. 이번 목적을 가장 작은 범위로 검증할 수 있다.
2. 브라우저 확장과 대화 UI부터 개발. 설치 경험을 개선할 수 있지만 재생 상태·학습 기록을 다루는 공통 규칙도 함께 새로 설계해야 한다. 후속 단계로 둔다.
3. 외부 LLM을 계속 호출하는 독립 튜터. 자동화 범위는 넓지만 모델 인증·비용·대화 화면이 추가되고, 기존 AI와 같이 공부하려는 현재 흐름과 겹친다. 이번 범위에서 제외한다.

이번에는 1번을 선택한다. 일반 브라우저 지원과 MCP는 이 계층을 재사용하는 후속 작업이다. 연결 방식 자체를 독점적인 기능으로 홍보하지 않는다.

## 구성과 저장 책임

기존 `events.jsonl`은 수집기만 쓴다. 새 학습 세션은 같은 비공개 디렉터리에 별도 `study.json`을 저장한다. 학습 세션은 수집기 저널을 수정하거나 수집기의 잠금을 공유하지 않는다.

`study.json`은 세션 식별 정보, revision, 현재 모드, 반영 완료 커서, 보류 중인 배치, 저장된 학습 항목을 한 문서에 가진다. 임시 파일 작성 후 원자적 교체로 갱신하고 별도 단일 작성자 잠금과 revision 검사를 적용한다. 잠금 충돌은 실패로 반환하고 기존 잠금을 자동 삭제하지 않는다. 소비자 파일의 부분 갱신 때문에 설명은 사라지고 커서만 전진하는 상황을 막는다.

`notes.md`와 기계가 읽을 수 있는 내보내기는 `study.json`에서 재생성한다. 내보내기 실패 시 세션 원본을 보존하며 다시 실행할 수 있다. 기존 사용자가 작성한 `notes.md`는 덮어쓰지 않는다. 최초 생성 시 대상 파일이 있으면 다른 명시적 출력 경로를 요구한다. 도구가 생성한 파일만 추적해 갱신한다.

수집 데이터와 학습 상태를 잘못 결합하지 않도록 초기화 시 수집 저널의 첫 이벤트 식별값과 해시를 기록한다. 다른 세션으로 교체되거나 반영한 커서보다 저널이 짧아지면 처리를 중지한다. 완료되지 않은 마지막 JSONL 행은 기존 읽기 규칙대로 기다리며 복구 목적으로 쓰지 않는다.

## 세션 모드와 배치 수명 주기

모드는 `follow`, `question`, `catch-up` 세 가지다. 이는 호스트 AI가 스킬에 따라 전환하는 상태이며, 라이브러리가 사용자 대화를 감청하거나 자체적으로 모델을 깨우는 기능은 아니다.

- `follow`: 아직 반영하지 않은 증거를 순서대로 제공한다. 의미 있는 경계에서 부연설명을 작성한다.
- `question`: 사용자의 질문과 당시 수집 위치/반영 완료 위치를 기록한다. `study next`는 상태만 반환하고 증거 배치를 제공하지 않는다. 기존 수집기는 계속 실행하고, 이미 제공한 배치는 보존한다. 기존 배치는 모드 전환 후 재개한다.
- `catch-up`: 기존 보류 배치부터 재개하고 미반영 증거를 차례로 제공한다. 질문 중 지나간 내용을 건너뛰지 않는다.

배치 제공은 반영 완료 커서를 이동시키지 않는다. 배치에는 세션 ID, 영속적인 receipt ID, 제공한 이벤트 ID 목록, 다음 커서, 제공 시 관찰한 저널 끝 위치, `hasMore`가 포함된다. 하나의 미완료 배치만 보유하며 재시작·재요청 시 동일 배치를 반환한다.

호스트 AI는 배치를 읽고 학습 항목과 배치 처리 기록을 함께 저장한다. 유효한 receipt에 대한 저장이 성공했을 때만 반영 완료 커서를 이동시킨다. 동일한 저장 키와 동일한 내용으로 재시도하면 중복 항목을 만들지 않는다. 같은 키의 다른 내용, 알 수 없거나 다른 세션의 receipt, 순서를 건너뛴 커서는 거부한다. receipt는 임의의 시간 제한으로 폐기하지 않는다.

배치 처리는 각 이벤트를 `noted` 또는 `reviewed`로 분류한다. `noted`는 항목에 연결한 증거이고, `reviewed`는 제어 이벤트·자막 반복 등으로 기록하지 않은 근거와 사유다. 이것은 에이전트의 처리 선언이며 학습자의 이해도를 증명하지 않는다. 모든 제공 이벤트에 처리가 있어야 배치를 완료한다.

큰 이벤트가 바이트 제한을 넘어 참조로 제공되면 원문을 제한된 조각으로 읽는 경로를 제공한다. 해당 receipt에서 원문 끝까지 읽기 전에는 배치 완료를 허용하지 않는다. 여러 조각을 읽었다는 사실도 의미를 이해했다는 보장은 아니다. 바이트 제한은 기본 12000, 최소 2048이며 JSON 메타데이터를 포함한다. 더 작은 값은 조용히 늘리지 않고 거부한다. 이미지 참조는 세션 디렉터리 내부의 실제 frame 이벤트 파일로 제한한다.

따라잡기 완료는 특정 관찰 시점의 저널 끝까지 반영했음을 뜻한다. 수집기가 그 직후 증거를 추가할 수 있으므로 `caughtUpThrough`와 판단 시각을 함께 반환한다. 새 이벤트가 없다는 이유만으로 강의가 종료됐다고 판단하지 않는다. 모드 전환은 명시적으로 수행한다.

## 재생 상태와 시간 표현

접근 가능한 플레이어에서는 play/pause/ratechange 이벤트와 관찰한 currentTime/paused/playbackRate를 기존 큐에 추가한다. 기존 seek 이벤트와 함께 저장하며, 종료·문서 교체·오버플로 처리 규칙을 유지한다.

되감기는 이전 증거를 지우지 않는다. 이벤트 ID 순서가 수집 순서의 기준이고 seek는 별도 경계다. 여러 번 본 같은 재생 시각도 다른 관찰로 보존한다. 배속으로 재생 시각을 추정하거나 되감기 전후의 차이를 미학습 시간으로 계산하지 않는다.

접근성 관찰 방식에서는 확인할 수 없는 재생 시각과 상태를 `null`/unknown으로 둔다. 기록은 이벤트 ID와 관찰 시각을 사용한다. 사용자 질문 모드는 이런 플레이어에서도 동작하지만 정밀한 강의 시각 연결은 주장하지 않는다.

이미지의 수집 시작 시각과 자막 관찰 시각을 보존한다. 같은 배치에 포함됐다는 이유로 화면이 특정 발화와 정확히 동시에 관찰됐다고 표시하지 않는다.

## 학습 항목과 근거

학습 항목은 다음 종류를 구분한다.

- `lecture`: 관찰한 강의 내용. 존재하는 caption/frame 이벤트의 근거가 필수다.
- `explanation`: AI의 부연설명. 강의와의 연결 근거를 기록한다.
- `correction`: 강의 표현에 대한 보완/정정. 대상 증거와 확인한 외부 출처 또는 미검증 표시가 필수다.
- `question` / `answer`: 사용자 질문과 답변. 질문 시점 및 관련 근거를 보존한다.
- `open-question`: 확인하지 못한 내용이나 후속 학습 항목.

근거 ID는 현재 세션의 실제 이벤트여야 한다. 관찰 지연 같은 상태 이벤트를 강의 주장 자체의 증거로 사용할 수 없다. 외부 출처는 URL과 제목, 확인 여부를 저장한다. 단순한 URL 등록을 자동 사실 검증으로 간주하지 않는다.

정정은 원래 강의 내용이나 이전 항목을 삭제하지 않고 연결된 별도 항목으로 남긴다. 강의 주장, AI 해석, 외부 확인 결과를 문서에서 구분한다. 자막과 화면의 텍스트는 지시가 아닌 신뢰하지 않는 자료로 다룬다.

`caption-overflow`, `observation-gap`, `interruption`은 문서에 남긴다. 실제로 유실된 이벤트 수와 단순 관찰 지연을 구분하고, 누락 내용을 재구성했다고 주장하지 않는다. 자동 되감기·재생 조작은 이번 범위에 없다.

## 제안하는 CLI와 에이전트 사용 흐름

기존 `capture`, `batch`, `stop`, `export`는 호환성을 유지한다. 아래는 이번에 추가한 `study` 인터페이스다.

1. `study init --out SESSION`: 수집 세션을 확인하고 학습 상태 초기화.
2. `study mode --out SESSION --mode question --file QUESTION_JSON`: 사용자 질문과 현재 위치 저장.
3. `study mode --out SESSION --mode catch-up`: 질문 답변 후 미반영 배치 재개.
4. `study next --out SESSION --bytes 12000`: 보류 배치 또는 다음 증거 반환. 전체 직렬화 응답을 UTF-8 바이트 제한 안에 유지한다.
5. `study evidence --out SESSION --receipt ID --event ID --offset N --bytes 12000`: 큰 원문을 참조로 제공했을 때 제한된 조각으로 읽기. 이미지 파일은 선택된 로컬 파일 참조로 제공한다.
6. `study commit --out SESSION --file COMMIT_JSON`: receipt·저장 키·학습 항목·이벤트별 처리 내역 검증 후 함께 저장.
7. `study status --out SESSION`: 수집/제공/반영 위치, 모드, 남은 이벤트 수, 불확실성 표시.
8. `study export --out SESSION`: 결합된 학습 문서 생성. 명시적인 출력 옵션으로 기존 수동 노트와 충돌 회피.

질문과 답변처럼 수집 배치와 독립적인 항목은 별도 `study note --out SESSION --file NOTE_JSON`으로 저장한다. 동일한 근거 검증과 저장 키 중복 방지를 적용하지만 수집 커서는 이동하지 않는다.

수업 종료 때는 수집기 종료/중단을 확인하고 남은 배치를 반영한 뒤 문서를 생성한다. 호스트 AI의 대화 문맥과 실제 모델 사용량은 별개다. `modelCalls=0`을 학습 과정의 토큰 사용량으로 제시하지 않는다.

## 범위와 의존성

- Node 22+와 기존 `pngjs` 외에 제품 의존성을 추가하지 않는다.
- 현재 CLI/라이브러리와 설치된 Codex 스킬을 확장한다. 자체 모델 호출이나 API 키를 요구하지 않는다.
- 음성 수집/ASR, 상시 대화 오버레이, 자동 재생 제어, 자동 누락 복구, 일반 브라우저 확장, MCP 서버는 이번 버전에 포함하지 않는다.
- 비공개 강의 자료와 생성 노트는 기존 ignored `sessions/`에 둔다. 공개 저장소 생성·푸시·강의 자료 업로드는 수행하지 않는다.
- 스킬 개정은 기능 구현 후 실제 명령에 맞춰 진행한다. 아직 없는 기능을 설치된 스킬에 안내하지 않는다.

## 구현 후 검증할 시나리오

1. 질문 모드 동안 수집 이벤트가 늘어도 커서는 이동하지 않는다. 답변 후 모든 배치를 순서대로 제공한다.
2. 배치 제공 후 프로세스가 종료되면 동일 receipt가 재등장한다. 저장 완료 후 재시도해도 항목이 중복되지 않는다.
3. 저장 실패, 오래된 revision, 동시 작성자, 다른 세션 receipt는 커서와 항목을 부분 갱신하지 않는다.
4. 너무 큰 이벤트를 원문 확인 없이 완료할 수 없다. 한글을 포함한 배치/원문 조각도 전체 응답 바이트 제한을 지킨다.
5. 존재하지 않는 근거와 처리하지 않은 이벤트를 거부한다. 정정은 원본을 보존하고 미검증 여부를 내보낸다.
6. 재생·일시정지·배속·앞/뒤 seek를 기록하고, null mediaTime과 관찰 지연을 잘못된 시간/누락 주장으로 바꾸지 않는다.
7. 수집기와 소비자가 동시에 실행되고 종료 직전에 새 이벤트가 생겨도 특정 시점 이후의 완전성을 주장하지 않는다.
8. 기존 수동 노트 파일은 보존한다. 내보내기 실패 후 재실행으로 저장된 항목을 복구한다.
9. 기존 테스트와 실제 브라우저의 합성 플레이어 테스트를 실행한다. 실제 강의 공동 수강은 별도 검증으로 기록한다.

## 후속 단계

동일한 합성 강의/질문 스크립트를 사용해 수집 결과, 미반영 증거, 설명 지연을 반복 측정하는 벤치마크를 만든다. 실제 모델 사용량을 측정할 때는 입력·캐시·출력을 분리하고 비교 조건을 맞춘다. 이 결과를 확인한 뒤 일반 브라우저 연결과 설치 절차를 개선한다. 현재 설계만으로 토큰 절감률이나 오픈소스의 성공 가능성을 수치로 주장하지 않는다.
